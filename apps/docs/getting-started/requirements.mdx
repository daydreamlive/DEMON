## Hardware

| Component | Requirement |
|---|---|
| GPU | NVIDIA, CUDA-capable. Tested on RTX 3090, 4090, and 5090; H100 is used for cloud deployments. |
| VRAM | ~24 GB for full TensorRT mode with 60 s engines (RTX 4090 class). Less is workable with mixed backends, shorter engine durations, and `--offload-text-encoder`. |
| Audio | Any output device; the web demo plays through the browser. |

<Note>
No GPU? Use the hosted instance at
[music.daydream.live](https://music.daydream.live) — see
[Hosted Demo](/cloud/hosted-demo).
</Note>

## Software

| Component | Requirement |
|---|---|
| Python | 3.11 (pinned in `pyproject.toml`) |
| [uv](https://docs.astral.sh/uv/) | Used for all installs and run commands |
| CUDA | 12.8 (baked into the pinned `torch==2.9.1+cu128` wheels) |
| TensorRT | 10.16.x (installed by `uv sync`; only needed for the TRT backends) |
| Node.js | 20+ — only for the bundled web demo; `node_modules` installs automatically on first run |
| OS | Windows and Linux are both used day-to-day (the hosted deployment runs Linux) |

## Browser (for the web demo)

- Any modern Chromium or Firefox.
- **Web MIDI** (hardware controllers) requires Chromium on `localhost` or HTTPS.
- **Webcam motion input** has the same secure-origin constraint.
- Audio playback requires one user gesture — the *click to begin* button counts.

## Models and disk

Checkpoints, fixtures, LoRAs, and TensorRT engines live under a single model
root, by default:

```text
~/.daydream-scope/models/demon/
```

Override it with the `ACESTEP_MODELS_DIR` environment variable. ACE-Step v1.5
checkpoints and audio fixtures auto-download on first use (fixtures come from
the [`daydreamlive/demon-fixtures-v2`](https://huggingface.co/datasets/daydreamlive/demon-fixtures-v2)
Hugging Face dataset). LoRAs are *not* auto-downloaded — drop `.safetensors`
files into `$ACESTEP_MODELS_DIR/loras/`.

<Warning>
TensorRT engines are **not portable**: they are specific to the TensorRT
version, CUDA stack, driver, and GPU architecture they were built on. Rebuild
after changing any of those. See [TensorRT Engines](/getting-started/tensorrt).
</Warning>
