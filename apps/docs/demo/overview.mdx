The demo app (`demos/realtime_motion_graph_web`) is DEMON's flagship reference
application: a Python backend plus a Next.js front-end in a single launcher.
Feed it audio and a prompt, then twist knobs, draw automation curves, blend
prompts, hot-swap timbre and structure references, and toggle LoRAs while the
model generates and plays back continuously. Most of the engine surface is
exposed as a live control.

It is the same application that powers the hosted instance at
[music.daydream.live](https://music.daydream.live).

<img src="/images/hud-live.png" alt="The DEMON demo app — live HUD view" />

## Launch

```bash
uv run python -u -m demos.realtime_motion_graph_web.run
# then open http://localhost:6660
```

Backend flags go after `--` (acceleration, checkpoint, ports — see the
[CLI reference](/reference/cli)). First run installs the web dependencies
automatically.

## How it fits together

The launcher starts two processes:

| Port | Process |
|---|---|
| `:6660` | Next.js front-end (React + zustand) — what you open in the browser |
| `:1318` | Python backend — HTTP API + WebSocket; one GPU `StreamingSession` per connected tab |
| `:1319` | Control bus (localhost-only) — lets the [MCP server](/advanced/mcp) drive your session |

Audio streams to the browser as zstd-compressed float16 delta slices over the
WebSocket; an `AudioWorklet` patches a shared PCM ring buffer in place, with
50 ms crossfades on swaps. The wire format is fully documented in the
[WebSocket protocol reference](/reference/websocket-protocol).

## Drive it from an LLM

Every user-facing action in the demo is also exposed as an MCP tool — prompt
changes, knob moves, LoRA toggles, source swaps, even sample-exact audio
writes into the live source. Point Claude Code (or any MCP client) at the
onboard MCP server and it controls the session you have open in the browser,
with the UI mirroring every change. See [MCP Control](/advanced/mcp).
